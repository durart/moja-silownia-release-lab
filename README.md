3. Import these files at the root of the lab, preserving `.github/workflows`. Verify `Lab CI / lab-regression` succeeds. This initial owner-approved bootstrap predates branch protection. `LAB_RELEASE_ENABLED` must remain absent or false. No actual Pages deployment is authorized by the bootstrap.

In lab Settings > Rules > Rulesets create an active branch ruleset targeting `main`; no bypass actors, require PR, one approving review from a distinct owner, dismiss stale approvals, require conversation resolution, require unique `lab-regression` status check from GitHub Actions and strict up-to-date status checks, block force pushes and deletion. 5. In lab Settings > Actions > General use read-only default token permissions, disallow Actions PR approval, GitHub-hosted runners only. Limit actions if supported to the pinned actions used here. With one identity and self-review prevention the owner cannot approve their own dispatch; this is intentional fail-closed. Do not enable release until reviewer and initiator roles are verified and the owner explicitly agrees to the isolated tests.
7. Settings > Secrets and variables > Actions > Variables: `LAB_RELEASE_ENABLED=true` only when step 6 is confirmed. Dispatch from the distinct test actor, not the owner, with exact `main` SHA. Owner checks prepare job summary and proposed mode/digest, then approves or rejects. A successful lab publication uses the separate URL `https://durart.github.io/moja-silownia-release-lab/`. Never publish to production during this exercise.

## Test and evidence
`node --test tests/*.test.mjs` and `node scripts/verify.mjs digest site` run without external dependencies. See `ACCEPTANCE.md` for real GitHub test cases. The tests in `tests/` are local code tests and do not prove GitHub enforces rules. The example workflow builds a single synthetic page and archives it for 14 days. The rollback verifies prior successful deploy job and the previous owner-recorded content SHA-256; it must still be reviewed as a separate deployment. GitHub pending concurrency jobs may be replaced by a newer one even with `cancel-in-progress: false`; record this in AT-10. The post-review main SHA check is not an atomic lock against future updates. Approvals apply to the exact run/artifact, not to an arbitrary later revision. Before using this pattern in production, verify immutable artifact custody, real rollback, full application coverage, and independently enforced owner authorization.
